# Phase 2 — Economy slice

Goal: from an empty start the player builds a base with Factorio logistics and produces an army; the barracks turns items into walkers. Success = build order from zero to a 10-walker army in ~8 minutes, controlled entirely from the RTS camera.

Built on Phase 1 (`PHASE1.md`) and the spike verdicts (`research/spikes.md`, decisions 7–8 for barracks and AI construction).

## Economic model (RTS over Factorio)

| RTS concept | Factorio implementation |
|---|---|
| Command Center (CC) | Composite placed at match start: `rts-command-center` (roboport clone, 40×40 construction area, 20 construction + 10 logistic bots, large electric supply area), a hidden `rts-core-power` (`electric-energy-interface`, 4 MW, under the CC), 4 `rts-stockpile` (storage chest clones, logistic storage). Losing all CCs loses the match. |
| Minerals | Iron, copper, stone, coal ore patches near each spawn (generated by `match.lua`). |
| Workers (SCV) | Construction bots from the CC. Player places ghosts in remote view; bots build from items in the logistic network. |
| Resource pool | Every item in the force's logistic network (storage/provider chests). HUD shows iron/copper plates, circuits, steel, power headroom, bots idle/total. |
| Supply / gas | Electricity. CC provides 4 MW; `rts-solar-array` (solar panel clone, 400 kW, no night: arena runs with `always_day`) adds more. Drills, smelters, barracks, factory all draw power. Brownout slows everything, like supply block. |
| Gathering | `rts-extractor` (electric mining drill clone, 2×2, output into a chest/belt placed at its drop position) → belts/inserters → `rts-smelter` (electric furnace clone) → inserters → `rts-stockpile` / passive provider chests. This is the Factorio half: logistics are manual. |
| Production buildings | `rts-barracks` and `rts-factory` are assembling-machine clones with their own crafting categories. They **pull ingredients from the logistic network by script** (every 30 ticks: if the current recipe lacks ingredients and the network has them, `network.remove_item` + `insert`). So consumers behave like RTS buildings (global pool), while producers stay Factorio. |
| Units | Recipes in `rts-barracks`: walker kit (10 iron, 2 copper, 3 s), heavy walker kit (30 iron, 10 copper, 5 steel, 8 s). Finished kits are spawned at the rally point (predictive scheduling from spike #4). |
| Buildings | Recipes in `rts-factory`: extractor, smelter, solar array, belts (×10), inserters (×5), poles (×5), barracks, factory, turret. Output goes to the barracks-style output slot, and the script moves finished building items into the network (`insert` into the nearest stockpile; if full, keep in output). |
| Defense | `rts-turret` (gun turret clone, needs ammo: `rts-ammo` recipe in factory from iron; script keeps turrets fed from the network, 10 rounds at a time). |
| Starting stock | In the stockpiles: 200 iron plate, 100 copper plate, 2 extractors, 2 smelters, 1 barracks, 20 belts, 10 inserters, 10 poles. First walker is possible within ~2 minutes. |

## Player interaction

- **Build menu** in the HUD (new tab row: Economy / Military / Defense). Clicking a building button sets `player.cursor_ghost = item` (ghost in cursor, vanilla placement in remote view, rotation with R). After `on_built_entity` for a ghost, re-give the RTS cursor only when the player presses Escape/Q or right-clicks (so they can place several); the cursor module already re-inserts the tool when the cursor empties.
- **Rally point**: with a barracks selected (selection must accept own buildings of kind `barracks`), right-click ground sets its rally point (stored in `storage.buildings[unit_number].rally`).
- **Production queue**: selecting a barracks shows its recipe buttons (walker / heavy); clicking sets the recipe (`entity.set_recipe`) and shows progress; the HUD shows the production count per kind. Continuous production: a building keeps producing while it has a recipe; a "pause" button clears it.
- **Resource HUD**: top strip shows iron, copper, steel, circuits (network `get_contents`), power (satisfaction % from the CC's electric network: `entity.electric_network_statistics` or `energy` ratios), bots.
- **Building selection**: left click on an own building selects it (single), showing its panel; box select still picks units only (filter `spider-unit`/`unit`), unless the box contains only buildings.

## Data stage additions (`prototypes/buildings.lua`, `prototypes/items.lua`, `prototypes/recipes.lua`)

- Clone the vanilla prototypes listed above with `rts-` names, trimmed costs, slightly higher health, graphics from vanilla with a tint where possible. Items with their own icons (vanilla icons tinted). Recipe categories `rts-units`, `rts-buildings`. All recipes enabled from the start (no research in Phase 2). Hide the vanilla crafting categories from these machines so vanilla recipes cannot be set.
- Map settings: `always_day` on the arena surface, pollution off, enemy expansion off.

## Control stage additions

- `scripts/buildings.lua`: registry `storage.buildings[unit_number] = {entity, kind, force, rally}` for CC, barracks, factory, turret, extractor, smelter; register on `on_built_entity`/`on_robot_built_entity`/`script_raised_built`; cleanup on death; `buildings.for_force(force, kind)`.
- `scripts/production.lua`: the script pull from the logistic network (consumers), finished-kit spawning (barracks), finished-building-item hand-off to the network (factory), turret feeding. Use predictive scheduling (spike #4) with a 60-tick fallback sweep.
- `scripts/economy.lua`: HUD-facing summaries per force (network contents, power, bots), cached every 30 ticks.
- `scripts/match.lua`: place the CC composite for each force via `build_blueprint`-free direct `create_entity` (identical bases at match start → `clone_area` is acceptable), generate ore patches (`create_entity{name="iron-ore", amount=...}` on a 12×12 blob per resource, 25–40 tiles from the CC), starting stock in the stockpiles.
- `scripts/hud.lua`: build menu, building panel, resource strip (extend, keep Phase 1 layout).
- `scripts/selection.lua`/`orders.lua`: single-click building selection, rally point setting.
- Enemy force in Phase 2 keeps the Phase 1 "spawn an army" brain but now spawns from its own barracks stock: give the enemy a prebuilt base (same composite + 2 extractors + 2 smelters + barracks wired with belts, built via `clone_area` from a template the match script builds on a scratch area) so its production is real. Real AI build orders are Phase 3.

## Dev loop and acceptance

- Headless autotest: build the player base by script (same template as the enemy), set recipes, assert that kits are produced and spawned, and that factory items reach the network; log "[rts] autotest" lines; zero errors in `tools/headless-run.sh 180 '\[rts' mods`.
- GUI screenshot run: HUD with resources and build menu visible; CC composite rendered; ore patches visible.
- Interactive QA via Codex: place an extractor on ore from the build menu, bots build it, belt to a smelter, set a barracks recipe, see a walker spawn at the rally point.

Acceptance checklist:
1. Match starts with a CC composite, stockpiles with starting stock, ore patches, 20 bots.
2. Build menu places ghosts; bots build them from the stock; power network forms around the CC.
3. Extractor → belt → smelter → inserter → stockpile loop works with vanilla logistics.
4. Barracks pulls plates from the network, produces kits, spawns walkers at the rally point; HUD shows the counts.
5. Factory produces building items into the network; bots use them.
6. Resource strip and power readout are correct within one refresh (30 ticks).
7. Enemy base produces walkers from its own barracks and keeps sending waves; destroying its CC wins.
